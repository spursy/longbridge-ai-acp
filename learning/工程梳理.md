# longbridge-ai-acp 工程梳理

> 面向中立 Provider 的 **Agent Client Protocol（ACP）** 运行时库,供 Longbridge 系列产品复用。
> 版本:0.1.0 · edition 2021 · License Apache-2.0

---

## 一、这个工程实现了什么功能

`longbridge-ai-acp` 是一个**可嵌入的 ACP 桥接库(crate)**,把"Longbridge AI 智能体"和"ACP 客户端/宿主"两端打通。它同时支持 ACP 协议的**两个方向**:

1. **作为 Agent(服务端)** —— 把一个 Longbridge AI 智能体暴露给 Zed 等标准 ACP 客户端。
   - 通过 stdio 对外说 ACP 协议。
2. **作为 Client(客户端)** —— 让原生 Rust 桌面 UI 去连接外部 ACP 智能体(如 **Codex**、**Claude**)。
   - 通过官方 ACP SDK 以子进程方式拉起外部 adapter。

### 核心设计理念:Provider 中立

- **本库不包含任何 Longbridge OpenAPI SDK、私有桌面 API、接口地址或凭证处理**。
- 宿主(host)自己实现 `AgentBackend` trait,带上自己的 API client、endpoint、鉴权流程和不透明的 session 状态。
- 不同产品各自提供适配器:
  - CLI 把 OpenAPI 适配放在 `longbridge-terminal`;
  - Longbridge Pro / Longbridge AI Desktop 提供各自的私有 API 适配器。

### 关键能力:富响应兼容(Response Compatibility)

服务端用**两层**保留"provider 富响应",兼顾通用客户端和 Longbridge 自家客户端:

| 层 | 内容 | 面向谁 |
| --- | --- | --- |
| 标准 ACP 表示 | Markdown 表格 / 链接 + plans / tool 进度 / 会话标题 | 通用 ACP 客户端 |
| 原生事件 | 完整 provider 事件放在 `_meta["longbridge.ai/event"]` | Longbridge 客户端(复用现有 Chat UI) |

- 标准 fallback 与原生事件配对时,打上 `longbridge.ai/standard-fallback` 标签:
  - Longbridge 客户端**忽略**被标记的 fallback 块,用原生事件重建富 UI;
  - 通用客户端**忽略**带命名空间的原生事件,只收可移植 fallback。
  - 这样**避免图表重复**,又不降低通用客户端兼容性。
- **流式归一化(Streaming normalization)** 覆盖:`vis-chart`、`html-live`、`svg-inline`、`x-widget`、`[stock ...]`,以及引用形式 `[citation N]`、`[^N]`、`[N]`。
- **安全**:本库从不执行活跃 HTML;不安全的 SVG 直接**省略**,绝不原样回显源码。

### 图表静态预览(SVG)

- 每种**非地理类** `vis-chart` 都附带静态 SVG 预览,供通用客户端渲染:
  column、bar、line、area、pie、scatter、histogram、funnel、radar、boxplot、treemap、word-cloud、sankey、heat-map、dual-axes、mind-map、organization-chart、indented-tree、fishbone-diagram、network-graph、flow-diagram。
- 地图类(`pin-map`、`path-map`)和 `vis-text` 只保留 Markdown fallback。
- Tree / node-edge 类数据无法成图时,降级为可读的 Markdown 大纲或边表,而不是报 "Chart data is unavailable"。

### Turn 结果语义(Turn Outcomes)

- ACP 的 `StopReason` 无法区分"失败的 turn"和"完成的 turn":失败 turn 也会以 `StopReason::EndTurn` 结束,**保证一次坏 turn 不会拆掉整个连接**。
- 客户端通过 `_meta["longbridge.ai/event"]` 信封区分成败:

| `event` | `data` | 触发时机 |
| --- | --- | --- |
| `backend_timeout` | `timeout_seconds`, `active_tools` | 后端在非活跃超时内停止发事件 |
| `turn_failed` | `error_message`, `phase` | turn 失败 |

- `phase` 指示如何处理已渲染内容:
  - `prompt` —— 后端没接这个 turn,什么都没渲染;
  - `stream` —— 已渲染部分答案,失败信息要追加到后面;
  - `prompt_response` —— (由 `DesktopSession` 客户端侧发出)prompt 请求本身收到了 JSON-RPC 错误响应。
- 本库自己写的每句英文文案都打了 `standard-fallback` 标签 —— 客户端可以渲染自己的本地化文案,永不把硬编码英文当成模型输出展示。

### 各模块职责

#### `lib.rs` —— crate 入口
声明 6 个内部模块,`pub use agent_client_protocol as acp` 重新导出官方 SDK,并对外暴露三大类公共 API:backend 侧、client 侧、desktop 侧、rich_content 侧、server 侧的符号。

#### `backend.rs` —— Provider 中立的核心契约
- **`AgentBackend` trait**:宿主要实现的核心 seam(CLI 和桌面客户端共用)。
  - 关联类型 `Session`(宿主的不透明会话状态)。
  - `const SESSION_HISTORY`:是否支持 `session/list` 与 `session/load`。
  - 方法:`new_session`、`list_sessions`、`load_session`、`prompt`(唯一必须实现)。
  - `prompt` 返回一个 `BoxStream<AgentEvent>` 事件流。
- **`AgentEvent<Session>` 枚举**:协议适配器能理解的全部事件类型 —— 文本/思考(Text/Thought)、带元数据的 Content、工具开始/完成/进度(含 Rich 变体)、Plan、SessionTitle、NeedsInput、PermissionRequired、Notice、RichContent、Extension(透传到 `_meta`)、Finished/Completed。
- **`Prompt`**:把用户 prompt 拆成 `text`(扁平化文本)+ `attachments`(结构化附件块)。
- **`ATTACHMENT_META_KEY`** + `attachment_payload()`:附件块通过 `_meta` 标记,服务端据此路由到 `Prompt::attachments` 而不混进文本。

#### `server.rs` —— ACP 服务端(最大、最核心)
- **`acp_agent(backend)`** / **`acp_agent_with_auth_methods(...)`**:把一个 `AgentBackend` 包装成 ACP `Agent` 组件。
  - 处理 initialize(只支持协议 V1)、new_session、list/load session、prompt、cancel。
  - agent 名 `longbridge-ai`,实现名 `Longbridge AI`。
- **`serve_stdio(backend)`** / **`serve_stdio_with_auth_methods(...)`**:直接把后端通过 stdio 跑成 ACP 服务。
- **`RichTextFilter`**:流式文本归一化的状态机,把 provider 的富文本标记(图表/widget/股票/引用等)转成标准 ACP 更新 + 原生事件,并处理缓冲残留。
- 大量内部辅助:plan 优先级/状态映射、citation 渲染、widget/股票符号解析、HTML 文本降级、超时与 turn 失败信封(`turn_failed_update`、`backend_timeout_update`)。
- `BACKEND_INACTIVITY_TIMEOUT = 1 分钟`:后端静默超时阈值。

#### `client.rs` —— ACP 客户端侧
- **`with_session` / `with_initialized_session` / `with_external_session`**:运行一次持久 ACP 会话的三个入口。
  - `with_session`:对任意 agent transport(传 `acp_agent(...)` 则全程进程内;传 `ExternalAgent` 则拉起子进程)。
  - `with_initialized_session`:额外暴露协商出的 `AgentHandshake`(协议版本 / capabilities / 实现元数据)。
- **`ExternalAgent` / `ExternalAgentConfig` / `ExternalAgentKind`**:外部子进程智能体。
  - `ExternalAgentKind::Codex` → 可执行名 `codex-acp`;`ExternalAgentKind::Claude` → `claude-agent-acp`。
  - 原生 `codex`/`claude` CLI 本身不说 ACP,必须用单独安装的 adapter。
- **`ClientDelegate` trait** + **`DenyPermissions`**:权限请求回调;只读/纯聊天宿主可直接用 `DenyPermissions`(一律 Cancelled)。

#### `desktop.rs` —— 长生命周期桌面会话
- **`DesktopSession`**:拥有 ACP 连接(外部智能体时还拥有子进程),供 GPUI / Tauri 的 model 持有。
  - `connect`、`prompt`、`prompt_with_attachments`、`cancel`、`next_event`、`shutdown`、`split`。
  - 内部用 actor 模式(mpsc/oneshot 通道)驱动 `drive_session` / `drive_turn`。
  - `TurnFinished` 前再次 prompt 返回 `SessionControlError::Busy`。
  - 一次失败的 prompt 响应**只结束 turn,不结束 session**。
- **`DesktopSessionEvent`**:`Update` / `TurnFinished` / `Failed`。
- **`DesktopSessionHandle` / `DesktopSessionEvents`**:`split()` 后分离命令端(可克隆)和事件端(独占)。

#### `rich_content.rs` —— 富内容模型
- **`RichContent`**:版本化富内容(含 `content_id`、`kind`、`mime_type`、`data`、`fallback`、可选 `svg`)。
  - `RichContentKind`:Chart / Table / Svg / Html / Widget / Artifact。
  - `RichContent::chart(...)`:校验图表类型(23 种白名单)、生成 Markdown fallback、调用 `chart_svg` 渲染 SVG。
  - `RichContent::table(...)`:校验并生成 Markdown 表格 fallback。
- 常量:`CHART_MIME_TYPE`、`TABLE_MIME_TYPE`、`RICH_CONTENT_NAMESPACE`、`RICH_CONTENT_VERSION`。
- 工具函数:`charts_from_markdown`、`normalize_chart_type`、`supported_chart_types`。

#### `chart_svg.rs` —— 静态 SVG 渲染器
纯函数式地把图表 JSON 渲染成静态 SVG 字符串,覆盖 20+ 种图表,供不能执行脚本的通用 ACP 客户端显示预览。

### 依赖与工程质量

- 关键依赖:`agent-client-protocol 2.0`(启用 `unstable_auth_methods`)、`tokio`、`async-trait`、`futures`、`serde`/`serde_json`、`base64`、`uuid`、`thiserror`、`tracing`。
- **Lint 极严**:`clippy::all` 与 `clippy::pedantic` 都设为 `deny`。
- CI:`cargo fmt --check` + `clippy -D warnings` + `cargo test --all-targets` + `cargo test --doc`。

## 三、如何使用本工程

> 本 crate 是一个**库**,不是可执行程序。你通过实现 `AgentBackend` 或连接外部智能体来使用它。

### 场景 A:把自己的智能体暴露为 ACP 服务端(供 Zed 等客户端)

```rust
use longbridge_ai_acp::{serve_stdio, AgentBackend, AgentEvent, BackendError, Prompt};
use async_trait::async_trait;
use futures::stream::{self, BoxStream};
use std::path::Path;

struct MyBackend;  // 这里放你自己的 API client / 鉴权 / 会话状态

#[async_trait]
impl AgentBackend for MyBackend {
    type Session = ();

    async fn prompt(
        &self,
        _session: (),
        prompt: Prompt,
        _cwd: &Path,
    ) -> Result<BoxStream<'static, Result<AgentEvent<()>, BackendError>>, BackendError> {
        Ok(Box::pin(stream::iter([
            Ok(AgentEvent::Text(format!("echo: {}", prompt.text))),
            Ok(AgentEvent::Finished(())),
        ])))
    }
}

#[tokio::main]
async fn main() -> Result<(), Box<dyn std::error::Error>> {
    serve_stdio(MyBackend).await?;   // 通过 stdio 对外说 ACP
    Ok(())
}
```

### 场景 B:桌面 UI 连接外部智能体(Codex / Claude)或内嵌智能体

```rust
use longbridge_ai_acp::{
    acp_agent, AgentBackend, DenyPermissions, DesktopSession, DesktopSessionEvent,
};
use std::sync::Arc;

async fn run(agent: impl AgentBackend) -> Result<(), Box<dyn std::error::Error>> {
    let mut session = DesktopSession::connect(
        acp_agent(agent),                 // 内嵌;换成 ExternalAgent::new(cfg) 则连子进程
        std::env::current_dir()?,
        Arc::new(DenyPermissions),        // 只读/纯聊天宿主
    ).await?;

    session.prompt("Summarize my portfolio risk").await?;
    while let Some(event) = session.next_event().await {
        match event {
            DesktopSessionEvent::Update(update) => println!("{update:?}"),
            DesktopSessionEvent::TurnFinished(_) => break,
            DesktopSessionEvent::Failed(error) => return Err(error.into()),
        }
    }
    session.shutdown().await;
    Ok(())
}
```

- 连接外部 Codex/Claude:用 `ExternalAgentKind::Codex.config()` / `ExternalAgentKind::Claude.config()` 得到启动配置,再传给 `ExternalAgent::new(...)`。
  - 前提:系统已单独安装 `codex-acp` / `claude-agent-acp` adapter。
- 需要协商元数据(协议版本/capabilities)时用 `with_initialized_session`。
- 实现 `ClientDelegate` 把权限请求路由到产品自己的确认 UI;只读宿主直接用 `DenyPermissions`。

### 发送附件

```rust
let mut meta = serde_json::Map::new();
meta.insert(ATTACHMENT_META_KEY.into(), serde_json::json!({"oss_key": "k1"}));
let file = ContentBlock::ResourceLink(ResourceLink::new("chart.png", "oss://k1").meta(meta));
session.prompt_with_attachments("What is in this image?", vec![file]).await?;
```
标了 `ATTACHMENT_META_KEY` 的块会被服务端排除在扁平化文本之外,经 `Prompt::attachments` 原样交给后端。

## 五、一句话总结

> `longbridge-ai-acp` 是一个 **Provider 中立的 ACP 运行时库**:对上用 `AgentBackend` 让任意宿主接入自己的 AI 后端,对外既能把智能体**暴露成 ACP 服务端**(serve_stdio),又能作为**客户端连接 Codex/Claude 等外部智能体**(DesktopSession);核心价值在于**双层富响应兼容**(标准 ACP fallback + `_meta` 原生事件)和**安全的流式富内容归一化**(图表静态 SVG、股票/引用/widget 处理、不执行活跃 HTML),让 Longbridge 自家客户端和通用 ACP 客户端都能正确渲染同一份响应。
